# Auth private-socket prerequisite — bounded222, source only

**Finding:** pinned official Auth supports PostgreSQL Unix sockets. The current owned-fixture architecture does **not** supply that socket to an Auth process. A DSN change alone cannot solve this; socket sharing and its security/lifecycle policy require a material, separately approved mechanism. Nothing is implemented or adopted here.

## 3. Missing transport/security mechanism

[PG launch](../../scripts/fixture-postgres-config.mjs#L5-L10): private `/tmp/owned-postgres`, PGDATA beneath it, socket0700, TCP off, local **trust**/host reject. Accepted closed observations record PG OS100:101 and parent/data0700. [Creator](../../scripts/fixture-container.mjs#L17-L56) enforces network-none/no ports/**empty mounts**/cap-dropALL/NNP and fixed commands; [admission](../../scripts/fixture-docker.mjs#L25-L33) has no Auth migration/launch profile or executable-transfer/socket-mount operation. Existing PostgreSQL exec commands see the socket only because they run **inside its original container**.

A separate Auth image lacks that filesystem and UID access. A URL, shared network namespace, copied socket file or container ID cannot bridge this. Sharing the entire socket parent would also expose PGDATA; aligning UIDs indiscriminately worsens that risk. Crucially, with local **trust**, socket access can request **other DB roles**: the intended DSN username is not a least-privilege boundary.

## 4. Smallest conditional option; stop

Required decisions: UID/GID/DAC **and PostgreSQL role-authentication/trust boundary**, original Auth command/lifecycle custody, and mount creation/removal ownership. This materially changes today's no-mount/private-layer architecture; it is **not** approved, implemented or physically qualified. No custom relay, cross-image binary copy/composite image, namespace injection or privileged workaround is adopted.
