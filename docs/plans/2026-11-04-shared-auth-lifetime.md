## Minimal internal contract (implemented; real verification not established)

See the current receipt contract below.

- Capture an **owner lifetime before** awaiting existing hydration/refresh/persistence readiness. Refuse acquisition if a successful replacement/logout/terminal rejection/consistency latch retires that owner during preparation. Never adopt the replacement user after an await.
- Successful password login creates a new owner lifetime, even for the same user or A→B→A. Failed login/persistence with successful compensation preserves the previous owner. Initial hydration establishes the initial owner; suppressed hydration must never become an anonymous fallback.
- Refresh/live-status rotation within the same native refresh session is not an account replacement. Acquisition may join existing readiness and capture its renewed access credential. An already acquired operation keeps its exact access credential; it neither refreshes nor adopts new credentials between requests.
- Explicit local/default/global logout retires old leases synchronously with owned state clearing, before queued public notifications and independently of remote acknowledgement. Native refresh401 and storage-consistency latching also retire leases. If existing public generation/baseline guards forbid clearing after401, the still-current captured internal owner nevertheless terminates and cannot be reacquired; a committed replacement owner is never aborted by that old401. Existing public stale-result/cache/event, revocation and compensation semantics stay intact.
- Capture the access deadline. A lease is no longer usable at that JWT expiry even if the client subsequently refreshes. This is local cancellation/guarding, not server-side revocation or per-event verification. Own and release timers/listeners; ordinary completion requires `dispose()`.
- Lease fetch restricts dispatch to the validated same-origin record API, fixes captured Bearer (or explicit anonymous state), omits cookies/refuses redirects, composes caller cancellation, and checks retirement before dispatch and after Fetch delivery. Retired late bodies are cancelled, never handed to a consumer as current. No automatic retry, replay, renewal or anonymous fallback.

## Consumer result delivery and cleanup — private option A, no shared ABI change

Storage's source-bound counterexample invalidates `assertCurrent(); return result` followed by `finally { await dispose(); }` as a current-owner delivery guarantee. Normal disposal deliberately aborts/seals the lease: its synchronous abort handlers can log out before the returned Promise fulfills, and `assertCurrent()` is unusable afterward even when the original owner remains healthy. This is a consumer ordering error, **not a violation of Core's documented lease**. The same problem exists if a consumer awaits reader cleanup after its last fence. Returned decoder/readers and their cancellation/release remain separately consumer-owned.

Core and Storage agree on **A for current private observation research only**:

1. Keep the lease open while awaiting all consumer-owned decode/read work and actual reader cancellation/finalization; include reader-lock release before that obligation settles. Failed cleanup prevents verified publication. Hung/pending work remains owned and pending, or explicitly bounded-unconfirmed; it is never success.
2. Prepare a controlled stable **nonthenable** observation before the final fence. Do not pass an untrusted object/getter/thenable into Promise resolution: its `then` lookup can reenter logout during settlement.
3. Call `assertCurrent()` and synchronously settle the native producer-owned Promise in the same turn, with no intervening await, application callback or thenable adoption. This defines **producer delivery linearization**, not owner-currentness when arbitrary downstream `.then`/`await` code later runs.
4. Immediately initiate `dispose()` and retain its exact identity-stable receipt in separately owned tracked teardown. Register the pending teardown obligation before synchronous disposal can reenter; do not await it on the already-linearized result path or swallow its failure. Join independent obligations without fail-fast, preserve primary and cleanup failures, and keep a bounded timeout/error sticky after late settlement. The delivered observation does **not** assert complete Core cleanup.
